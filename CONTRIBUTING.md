## Code of Conduct

This project follows the [Contributor Covenant Code of Conduct](CODE_OF_CONDUCT.md). By participating you agree to uphold it. Please report unacceptable behavior to the maintainers via GitHub issues.

---

## Ways to Contribute

- **Bug reports** – with reproduction steps, expected vs actual, logs, OS/Tauri version
- **Feature requests** – describe the problem, not just the solution
- **Documentation** – README, comments, error messages, guides
- **Code** – bug fixes, performance, accessibility, tests, refactoring
- **Design** – UX improvements for Dashboard / Sessions / Analytics

No contribution is too small.

## Development Setup

### Prerequisites

| Tool | Version | Install |
|------|---------|---------|
| Node.js | `>=22` | https://nodejs.org |
| Rust | stable | https://rustup.rs |
| Tauri CLI | `^2.0` | `cargo install tauri-cli --version "^2.0"` |
| WebView2 | Windows 10+ | pre-installed on Win 10/11 |
| SQLite | `3.35+` (json1) | bundled via `rusqlite` |

On Windows you also need the [Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/).

Verify:

```bash
node -v
cargo --version
cargo tauri --version
```

### Fork & Clone

```bash
# 1. Fork on GitHub (chandupahashen/opencode-monitor → your fork)
# 2. Clone your fork
git clone https://github.com/<your-username>/opencode-monitor.git
cd opencode-monitor

# 3. Add upstream
git remote add upstream https://github.com/chandupahashen/opencode-monitor.git
```

Create a feature branch from `master` (or `main` – both are accepted):

```bash
git checkout -b fix/session-model-json
# or feat/analytics-heatmap, docs/readme, chore/bump-deps
```

## Project Structure

```
opencode-monitor/
├─ src/                      # React 19 + Vite + Tailwind v4 frontend
│  ├─ pages/                 # Dashboard, Sessions, Analytics, Projects, Settings
│  ├─ components/            # Layout, Titlebar, JsonPreview, Skeleton, etc.
│  ├─ hooks/useDb.ts         # Tauri invoke() wrappers
│  ├─ store/useStore.ts      # Zustand global store
│  ├─ utils/model.ts         # decodeModel() handles JSON/plain model ids
│  └─ types/index.ts         # Shared TS interfaces (must stay in sync with Rust)
├─ src-tauri/                # Rust backend (Tauri v2)
│  ├─ src/db.rs              # SQLite queries — JSON model extraction, project JOIN
│  ├─ src/models.rs          # Serialize structs + extract_project_name / extract_model_id
│  ├─ src/commands.rs        # Tauri commands (get_overview, get_sessions, …)
│  ├─ src/lib.rs             # AppState + plugin registration (store, updater, process)
│  ├─ capabilities/default.json
│  └─ Cargo.toml
├─ .github/workflows/build.yml  # CI: lint, test, signed MSI, update.json + auto-release
├─ update.json               # Updater manifest (generated by CI, not hand-edited)
└─ dist/                     # Vite build output (gitignored)
```

**Keep in sync:** If you change a Rust struct in `models.rs`, update the matching TypeScript interface in `src/types/index.ts`.

## Running Locally

```bash
# install JS deps
npm install

# dev with hot-reload (Vite + Tauri)
npm run tauri dev
# or frontend only
npm run dev        # → http://localhost:1420
```

Useful scripts:

```bash
npm run lint        # ESLint + type-check
npx tsc -b --noEmit # TypeScript only
cargo test --manifest-path src-tauri/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml
npm run build       # tsc + vite → dist/
```

### Tauri dev notes

- The app reads `opencode.db` read-only via `rusqlite` (bundled). Default locations:
  - Windows: `%APPDATA%/opencode/opencode.db`
  - Linux/macOS: `~/.local/share/opencode/opencode.db`
  - Fallback: `%LOCALAPPDATA%/opencode/opencode.db`
  - Override in **Settings → Database Path**
- `src-tauri/src/db.rs:open_db()` uses `busy_timeout(3s)` and best-effort migrations (`SCHEMA_VERSION = 2`) so a locked DB (opencode running) does not crash the monitor.

## Code Style & Quality

- **Frontend:** ESLint (`npm run lint`), TypeScript strict, Tailwind v4, functional components, `zustand` for state.
- **Backend:** `cargo fmt` / `cargo clippy` (if installed), `tracing` for logs, never `unwrap()` on user input — return `Result<_, String>`.
- **Commits:** keep diffs focused; one logical change per commit. See [Commit Convention](#commit-convention).
- **No placeholder files** — prefer editing existing files.

Before pushing:

```bash
npm run lint
npx tsc -b --noEmit
cargo check --manifest-path src-tauri/Cargo.toml
```

CI will run the same on `windows-latest` with Node 24.

## Database Notes

Current `opencode.db` (post-upgrade, 2026) stores:

- `session.model` as JSON `{"id":"deepseek-v4-flash-free","providerID":"opencode","variant":"max"}` (old: plain string).  
  Rust uses `model_key_expr()` → `COALESCE(CASE WHEN json_valid(model) THEN json_extract(model,'$.id') ELSE model END)` and collapses variants.
- `project` table (`id, worktree, name`) is authoritative; `session.project_id` is a hash FK. `get_project_stats` now `LEFT JOIN project`.
- `message` (45k rows) + `part` (212k rows) hold the conversation; `session_message` is legacy empty — `get_session_detail` queries `message` with `part` counts.
- `todo`, `event`, `workspace`, etc. exist but are not yet surfaced in the UI.

When adding a new query, handle both old (plain `model`) and new (JSON) and missing tables (`table_exists()` helper).

## Signing & Updater (Release)

The updater uses `tauri-plugin-updater` + `tauri-plugin-process`.

- `src-tauri/tauri.conf.json:plugins.updater` has dual endpoints:
  ```json
  ["https://github.com/chandupahashen/opencode-monitor/releases/latest/download/update.json",
   "https://raw.githubusercontent.com/chandupahashen/opencode-monitor/main/update.json"]
  ```
  plus `pubkey` (minisign) and `windows.installMode: passive`, `dialog:false`, CSP `connect-src` allows those hosts.
- `src-tauri/capabilities/default.json` must allow `updater:allow-download-and-install` + `process:allow-restart`.
- **Local signed build (no script needed):**
  ```powershell
  # set either naming — GitHub Actions syncs both automatically
  $env:TAURI_SIGNING_PRIVATE_KEY = Get-Content src-tauri/tauri-key.pem -Raw
  $env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = "your-password"
  # or TAURI_PRIVATE_KEY / TAURI_KEY_PASSWORD
  npm run build
  cargo tauri build --bundles msi  # uses src-tauri/tauri.conf.json:bundle.createUpdaterArtifacts
  ```
  If no env var, the MSI will be unsigned and `update.json` will contain an empty signature (updater disabled).
- **CI auto-release (no manual script):** Pushing to `main`/`master` triggers `.github/workflows/build.yml`:
  1. `lint-and-typecheck` + `test` → 2. `build` (Windows) resolves version from `package.json` (or `v*` tag) and runs `cargo tauri build --bundles msi` signed via `secrets.TAURI_PRIVATE_KEY`/`TAURI_KEY_PASSWORD` → 3. `release` creates/updates GitHub Release `v<version>` with `*.msi`, `*.sig`, `update.json` and syncs `update.json` to `main` (`[skip ci]`) for old clients. No `build.ps1`/`publish-github.ps1` needed — just bump `package.json`/`src-tauri/Cargo.toml`/`src-tauri/tauri.conf.json` together, commit and `git push origin main` (or push a `v*` tag). PRs run lint/test only.
- **Manual version bump:** keep `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json` in sync (all three).

Never commit `tauri-key.pem` or `*.sig` — they are gitignored.

## Commit Convention

We use Conventional Commits:

```
feat: group model variants in analytics
fix: handle unsigned builds gracefully
docs: update CONTRIBUTING with DB notes
chore: bump to 1.5.5
refactor(db): extract model_key_expr helper
```

Types: `feat, fix, docs, style, refactor, perf, test, build, ci, chore, revert`.

Keep subjects ≤72 chars, imperative mood, no trailing period.

## Pull Requests

1. Branch from `master` (or `main`) — `git checkout -b feat/…`
2. Keep PRs small and focused; larger changes → discuss in an issue first
3. Update `README.md` / `CHANGELOG.md` if user-facing
4. Ensure CI passes: `lint`, `tsc`, `cargo test`
5. Fill the PR template:
   - **What / Why**
   - **How tested** (e.g., `cargo check`, `npm run build`, manual DB at `~/.local/share/opencode/opencode.db`)
   - **Screenshots** for UI changes
6. One approval required; maintainers may squash on merge

Draft PRs are welcome for early feedback.

## Reporting Bugs

Use the **Bug report** issue template and include:

- OS, app version (`Settings → About` or `health_check`), Node/Rust versions
- Steps to reproduce (minimal)
- Expected vs actual
- Relevant logs: `%APPDATA%/opencode-monitor/logs/` or `~/.local/share/opencode-monitor/logs/`
- DB info: `SELECT sqlite_version(), COUNT(*) FROM session` if relevant (do not paste private prompts)
